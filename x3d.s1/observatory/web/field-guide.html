01 / Open the local laboratory

An API is unnecessary
for testing the architecture.

Launch from the x3d.loom repository root. The local server uses authored fixtures; no scene state is sent to TypeSafe.

Windows

Run the launcher.

Double-click x3d.s1/observatory/run.bat, or use Python in a terminal:

py -3 x3d.s1/observatory/server.py

Use a recent Python 3 installation; Python 3.12+ is the project target. Keep the terminal open while exploring.

WSL / Linux / macOS

Serve the same files.

python3 x3d.s1/observatory/server.py

# Open http://127.0.0.1:8810/
# Another port:
python3 x3d.s1/observatory/server.py --port 8811

Use the printed address. The X3D viewport needs a WebGL-capable browser; the scene preview and the inspection record serve different purposes.

The distinction that makes the laboratory useful: the local code really parses fixture bytes and computes observations. The probabilities are deliberately authored inputs. The required external witnesses remain outstanding in every generated rehearsal.

Select a fixture and rehearsal profile; move the probability and threshold. Compare the changing advisory route with the fixed requirements, not_run statuses and acceptance_eligible: false.

02 / Align with Loom's purpose

A useful assistant helps decide
what to inspect next.

Loom centres on a candidate, named instruments, observations and explicit acceptance conditions. A typed model can suggest investigation priorities; it cannot confer the authority of an instrument that never ran.

This is the implemented rehearsal boundary, not a diagram claiming that the complete external release pipeline was executed.

A probability can change the order of a question. It cannot retroactively run the instrument that answers it.

04 / Ask only what needs judgment

D / C / J is a design tool
for spending attention well.

Question classSource of an answerX3D applicationBoundary
D · decidableLocal code answers a defined source fact.Does this parsed document contain a geometry declaration? How many local lights are declared?A declaration answer is exact for that defined source query, not a prediction that the renderer will draw it.
C · exact twinA named validator or other exact instrument answers the stated predicate.Does this candidate satisfy a particular pinned XSD or semantic rule set?Do not ask a model to replace the available instrument. Instrument outcomes can become later evaluation labels.
J · judgmentNo exact twin has been specified for the question.Which part of a confusing scene should a reviewer inspect first? Which description best matches an intended teaching concept?A bounded advisory answer needs an explicit answer space, context and abstention policy. It supplies no release verdict.

A useful J question asks about one interpretation, rubric dimension or ordering decision. “Is this scene good?” bundles conformance, visibility, intent and beauty into an answer with no clear authority.

Record which state facets were requested, their trust tier and whether the budget dropped anything. Slicing removes information as well as bytes. Keep future evaluation labels outside the model input: supplying a validator result to a prediction judged by that result measures answer leakage.

05 / Read the number your policy actually uses

Concentration describes the answer.
Calibration needs observations.

The Observatory exposes an authored probability of continue and a routing threshold. These controls let you test policy behaviour without pretending that a model generated the answer. Moving a slider supplies a counterfactual input, not experimental evidence about Jev.

Choice confidence = (pmax − 1/n) / (1 − 1/n)

For a two-option Choice with probabilities continue: 0.85 and inspect: 0.15, the selected option has probability 0.85 and Choice confidence is 0.70. The confidence is calculated from the same distribution. Checking both numbers does not create a second independent observation.

Authored P(continue)Selected optionSelected probabilityChoice confidence
0.85continue0.850.70
0.50continue, by this rehearsal's explicit tie choice0.500.00
0.15inspect0.850.70

Low P(continue) can mean a confident selection of inspect. Name the option whose probability the policy consumes. Defer or escalate when that selected probability does not meet the configured bar.

Choice

One named alternative.

Retain the option distribution. A large winning probability is a model report; its real-world reliability must be evaluated on the relevant question and data.

Noul

One proposition.

Reported probability of yes/true. Give ambiguity an explicit unsure outcome; this value is not a measure of degree.

Score

One ordered rubric.

The mean can hide a split distribution. Use concrete level descriptions and inspect their probabilities. Ranking review work is separate from grading a release.

No calibration curve is claimed. A reliability diagram needs model-emitted probabilities paired with appropriate held-out outcomes. Synthetic sliders, a confidence formula and replayed examples cannot provide that measurement. Existing archived CSV arithmetic remains a separate historical analysis.

about where to spend effort.

These are teaching profiles, not registered Loom release profiles. Profile ID fixes membership in code with no advisory argument. Authored weights reorder the queue without removing or satisfying a requirement.

Every row selected by a profile is emitted as not_run. The planner checks eleven counterfactual distributions and records whether the requirement membership remains unchanged. This is an executable check of the local planner, not a proof about the complete external Loom system.

The displayed priority and cost units are authored teaching values. They are not measured latency, a learned probability of failure or a benchmark-derived saving. A future scheduler can compare policies experimentally while retaining the same required evidence contract.

Make the advisory lane powerful at allocation and deliberately powerless at acceptance.

07 / Reproduce what happened locally

Bind the record to bytes.
Keep its authority explicit.

The rehearsal binds candidate, state, question, policy and local code with full SHA-256 digests. Verification checks the content digest, reconstructs the run and compares the entire current record.

# From the extracted project root:
python3 x3d.s1/observatory/rehearsal.py run \
  --scene clean-rig --profile preview \
  --p 0.85 --threshold 0.80 --out rehearsal.json

python3 x3d.s1/observatory/rehearsal.py verify rehearsal.json

On Windows use py -3 in place of python3. The run command writes a local JSON record. Verification needs the same compatible candidate, code and configuration.

Matching replay establishes local self-consistency. It does not authenticate the producer or prove that an external instrument ran. A producer controlling both code and record can manufacture a consistent pair. The schema is x3d.s1.rehearsal/1; acceptance_eligible stays false.

The bounded JSON hash profile is x3d.s1.rehearsal-c14n/1: integral floats normalize to integers so browser JSON export preserves identity. It is not RFC 8785/JCS. Exact replay also records the Python version; use the interpreter that ran the server. Keep failure visible. Malformed JSON, duplicate keys and nonfinite JSON constants are refused by the rehearsal reader. A replay mismatch should remain a mismatch; it is a prompt to examine which identity changed, not a reason to replace the old record silently.

only when its contract holds.

09 / A visual integration worth building carefully

From an image rectangle
to an inspectable scene witness.

Box locates an image region, not an X3D world volume or DEF. A useful bridge adds an independent correspondence instrument.

  1. Freeze the observation.Bind candidate and resource bytes, renderer version, event time, active world camera, projection and viewport to an image capture.
  2. Record the proposed image region.Keep the Box coordinates in their declared image-relative frame, the question, model identity and original output. Treat the rectangle as a suggestion to inspect.
  3. Resolve candidate objects independently.Use a matched object-ID buffer or controlled picking pass to map image pixels to stable scene instance paths. DEF alone may represent multiple USE instances.
  4. Expose ambiguity instead of hiding it.Occlusion, transparency, overlapping instances and a rectangle spanning several objects can yield several candidates. Record that multiplicity.
  5. Verify the actual predicate.A source check, geometry check, reference comparison or human review answers the follow-up question. The suggestion remains advisory.
Future bridge, not a shipped model feature. The current package does not call Box or generate an ID-buffer witness. This sequence defines a narrow, testable extension that keeps image suggestions, scene correspondence and acceptance authority separate.

10 / Six experiments for curious builders

Predict one thing.
Change one thing.
Keep the record.

Hide the same bench.

Inspect the clean fixture, then the hidden Switch and zero-scale variants. Compare geometry declarations and local reference results with the preview. Explain why identical node counts need not produce identical visible objects.

Keep: fixture ID, declaration result and one sentence naming the missing renderer witness.

Invert the selected option.

Compare synthetic P(continue) = 0.85 and 0.15 with the same threshold. Predict the selected option, selected probability and confidence before moving the control.

Keep: both distributions and the option whose probability the policy actually used.

Move every slider to an extreme.

For one rehearsal profile, try 0, 0.5 and 1. Change the threshold too. Track queue order and outstanding requirements. Then switch profile and explain why its membership changes for a different reason.

Keep: required IDs, all witness statuses and acceptance eligibility for each case.

Read the counterfeit instructions.

Compare the clean fixture with untrusted-notes. Inspect the text-boundary observation and selected state. Identify what was excluded. Do not treat a regex match—or no match—as an injection proof.

Keep: the state facets, text-boundary scope and unchanged witness requirements.

Break an exact replay.

Generate a JSON rehearsal, verify it, and edit a copy. First change a recorded observation without changing its digest. Then compare records across a deliberate fixture/code change in a separate working copy.

Keep: the refusal, changed identity and explanation of why a digest is not independent authenticity.

Design the future shadow trial.

Specify one J question or C prediction, a frozen state-slicer version, model ID, target oracle and held-out split by scene/prompt family. Separate threshold selection from final evaluation.

Keep: the preregistered question, label provenance and failure metric. No model performance result exists until the trial runs.
