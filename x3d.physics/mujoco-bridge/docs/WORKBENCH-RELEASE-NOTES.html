Run it locally

  1. Extract the ZIP.
  2. On Windows, double-click START-Windows.cmd. With WSL, run bash START-WSL.sh and open the printed address. On Linux/macOS, run python3 start.py.
  3. Choose a lab, restart its experiment and select Measure 5 s. Pin the run, change one variable, and measure again.

The launcher requires Python 3 and serves only the local machine. The browser runs the actual simulation. The embedded production app needs no npm installation, API key or external simulation service. Directly opening the HTML is also an option where browser restrictions permit it.

Fresh verification

57 checks passed: 34 core engine, 14 workbench and 9 DOM integration checks.

The physics tests use actual MuJoCo 3.17.0 WASM. All eight presets and five extracted starters compiled and stepped. The production build passes strict TypeScript checking. The local launcher served the exact embedded build.

The arm achieved named tip–obstacle contact, positive final touch sensing and bounded target error. Repeated runs from the same reset produced identical complete sampled trajectories in the same runtime. Both positive and negative cartpole tilts recovered in the tested local regime. Trial cancellation preserved the live state.

Real browser / GPU verification remains open.

The cloud browser rejected local-file navigation and its localhost endpoint could not reach the build server. DOM checks use jsdom and real WASM, with canvas unavailable and dialog/download mechanics substituted. They establish component behavior, not WebGL quality, browser layout or Windows/WSL compatibility. Earlier browser evidence is explicitly historical.

Scope and boundaries

This is a learning and control workbench. The horizontal arm deliberately limits collision to its tip. Its controller is local joint PD; cartpole feedback is local regulation. There is no RL trainer, complete robot collision model, arbitrary asset-directory importer, Python simulation backend or X3D/game-engine bridge. Saved observations and trials are analysis records, not full integration-state replay checkpoints.

Live options remain distinct from source XML. Draft and note storage depends on browser availability. Runs and baselines remain in memory until reload; export them to keep a portable record. The current renderer supports primitives and a mesh subset; unsupported geometry is marked with pink placeholders and a warning.

Source and test evidence are included. See README.md and validation/README.md for exact commands, test substitutions, known limits and provenance. Original uploaded files were preserved.
