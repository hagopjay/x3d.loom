# Learnings: medical frontier (FMA, SNOMED CT ids, H-Anim on the torso)

Fold-back from x3d.demo `docs/demos/medical-provenance/v1/`. Educational proof of concept, not medical advice. Validator behind every scene claim: x3d_mcp `fa5dccf` `validate_xml` (XSD 4.1). Render checks: headless Chromium, software GL, X_ITE 16.6.0, not a performance number. Grades: **C** checked in the build, **L** third-party or earlier build, **S** judgement, scope doubt or gap. Local IDs `MP-n`; renumber on promotion to LOOM-v1.md.

| ID | Lesson | Evidence | Grade |
|---|---|---|---|
| MP-1 | **Mapping existence and mapping meaning are two claims.** An exact-label hit in FMA proves the class exists (C, 120 of 120 attempts). Whether the mesh *is* that class is a name judgement (L for 103, S for 18). Record both, with different grades. | `claims.json` kinds `fma-term` vs `denotes` | C |
| MP-2 | **Segmentation labels are names, not classes.** Scope mismatches (small bowel vs duodenum, colon vs rectum, merged portal and splenic veins, iliac extent, sets such as pulmonary veins) are exactly where the grade drops to S. | 18 S denotes claims | C |
| MP-3 | **A crosswalk chain beats a single lookup.** FMA to Wikidata (P1402, one item per id, 117 of 117) to Uberon to SCTID/MeSH/UMLS. Uberon's own FMA xref agreed with the start id for all 82 reached (0 disagreements), which is a free consistency check. | OLS4 and Wikidata SPARQL fetches in `data/ledger.json` | C |
| MP-4 | **Left/right is where chains break.** FMA has Left and Right classes; Uberon and SNOMED often one bilateral class, so 42 of 120 shapes (24 ribs, paired bones and veins) got no SNOMED id. A gap, not proof of absence. | `structures.json` | L |
| MP-5 | **H-Anim is a skeleton vocabulary.** 146 segment names in the X3D 4.1 XSD: vertebrae, skull, sacrum, pelvis, clavicle, scapula, arm and leg segments. No ribs, sternum, costal cartilage or organ. 37 of 121 shapes map; hip bone to pelvis is loose (L). | XSD parsed by `build.py` | C |
| MP-6 | **Injected `metadata` as first child of Shape validates** (XSD requires metadata before Appearance, as with Transform, see HG-2). 121 MetadataSets, both scenes 0 errors; source scenes were valid before. Validation time 2.4 s for a 2.8 MB torso. | x3d_mcp `fa5dccf` | C |
| MP-7 | **Cache raw bodies and log a ledger.** 202 fetches (url, sha256, bytes, time) make the build re-runnable offline and let a reviewer re-check any claim. | `data/cache/`, `ledger.json` | C |
| MP-8 | **Do not copy what you can reference.** The new scenes need textures from the older folder; rewriting `tex/` to a relative path to `brain-torso-xite/v1/scenes/tex/` kept the repo at 5.8 MB for the folder. | build step | C |
| MP-9 | **Licence texts on one site can disagree.** BodyParts3D info page says CC-BY SA 2.1 JP; lic.html (2025/02/27) says CC BY 4.0. FMA: OBO registry CUSTOM (inactive), OLS none. Follow the newer text, flag the conflict, ship ids only. | pages read 18 Nov 2026 | C |
| MP-10 | **Dataset licence upgrade.** Zenodo 10047292 (TotalSegmentator, 117 structures, 1228 CT) states cc-by-4.0; the earlier torso notice said Likely. Subject s1397 membership and the pyvista copy stay L. Zenodo answered from the container this time (an earlier note said blocked). | record JSON | C |
| MP-11 | **Small structures are voxel-limited.** One 3 mm voxel is 0.027 mL; structures under 5 mL (adrenals, ribs 11 and 12) carry S on their volume. | 4 claims | C |
| MP-12 | **Ontology ancestors make the mapping queryable.** FMA is-a ancestors via OLS4 hierarchicalAncestors for all 120 mapped shapes (120 C claims): 108 distinct non-generic classes (Organ 77, Bone organ 60, Long bone 30, Vertebra 25, Rib 24). "Select every Rib" is one filter, not 24 name matches. Labels can carry stray whitespace ('Arterial tree' + newline): trim. | v2 `claims.json` kind `isa` | C |
| MP-13 | **The scene can check itself against the claim file.** The page reads each shape's MetadataSet back from the running X3D scene and compares grade, FMA id, SNOMED id and claim ids with structures.json: 111 of 111 agree; editing one grade in memory is caught (110 of 111, shape named). Self-consistency only: an editor who changes both files defeats it, so a hash or signature is the next step. | headless Chromium, X_ITE 16.6.0 | C |
| MP-14 | **Bind claims to the scene with digests.** Per shape: SHA-256 of the canonical JSON (sorted keys, no spaces) of its claim list, stored in its MetadataSet; one root over sorted `uid digest` lines in the scene head (`claims-root-sha256`). The page recomputes with WebCrypto and `verify.py` does it offline: 111 of 111 torso and 10 of 10 brain digests match; one changed claim text is caught and named. Canonical JSON must match across Python and JS (ASCII keys, `ensure_ascii=False`). A hash is not a signature: an editor who rewrites both files and the root defeats it, so publish the root outside the folder (PR text, commit) and add a keyed signature once a key policy exists. | v3 `verify.py`, headless Chromium | C |
| MP-15 | **A real HAnimHumanoid from segmentation bones is cheap, the joint centres are the hard, ungradable part.** 35 joints and 35 segments (34 bones plus a pelvis from both hip bones) from the CT torso: valid (x3d_mcp `fa5dccf`, profile Full, HAnim level 2), all 70 names present in the XSD enumerations, forward kinematics reproduce the placement table to 0.000000 m. Every joint centre is estimated from mesh geometry (top 15 percent of femur and humerus, vertebra-pair midpoints), so each is S. | v4 `build.py`, `joints.json` | C structure, S centres |
| MP-16 | **Convention trap, solved by one Transform.** CT scene: +X patient-right, +Z posterior. H-Anim: body faces +Z, character's left at +X. A 180 degree turn about Y fixes both. Also: segment geometry must be offset by minus the joint's absolute position (and scaled mm to m) inside the HAnimSegment, because joints compose translations. | v4 scene | C |
| MP-17 | **The H-Anim gap is visible.** Ribs, sternum and costal cartilage have no segment name; they sit outside the humanoid (26 shapes). A biomechanics-grade model would need a ribcage vocabulary H-Anim does not have. | XSD check | C |
| MP-18 | **FMA keys open meshes.** BodyParts3D element lists map FMA concept ids to mesh element files, so a CT shape with an FMA class can be paired with an open mesh by id: 100 of 110 torso shapes (998 element files, 2.2 M source faces). Compound organs are unions of elements (liver 60). | `partof_element_parts.txt`, v5 `build.py` | C |
| MP-19 | **Find axes by looking at sides, not by search.** An automatic search over 48 signed axis permutations on noisy centroids chose a wrong frame (scale 0.65, median 59 mm). Reading the left kidney and the sternum fixed it: CT = (-x, z, y) of BodyParts3D. After that the robust similarity fit gave scale 0.9397, rotation 10.6 degrees, 31 mm median on the fitted set. | v5 `data/fit.json` | C |
| MP-20 | **A global fit cannot model posture.** 17 of 100 structures are 'far' (limbs with raised arms, neck vessels, iliac arteries 263 mm, whole-body skin vs trunk CT); spine is 10.8 mm median. The articulated v4 joints are the next fit. Chamfer distance between two people measures difference, not error. | v5 `data/metrics.json` | C |
| MP-21 | **Mesh licences can contradict their own files.** BodyParts3D OBJ headers: CC BY-SA 2.1 Japan; lic.html (2025/02/27): CC BY 4.0. The derived meshes ship under the stricter reading in a separate file with a notice. Pin the source zip by sha256, never commit it (65 MB), and decimate for the page (vertex clustering, 148 k faces, 952 KB gzip). | v5 `NOTICE-BP3D.md` | C |
| MP-22 | **Inline nodes are reachable through IMPORT/EXPORT, not through the SAI node.** In X_ITE 16.6.0 `Inline` exposes only its fields (no `getInternalScene`); EXPORT the materials in the inlined file, IMPORT them in the parent, then `scene.getImportedNode`. The validator accepts both. | v5 page and scenes | C |
| MP-23 | **The XSD and X_ITE disagree on volume children.** `OpacityMapVolumeStyle.transferFunction` cannot be written in XML that passes x3d_mcp `validate_xml` (the PixelTexture containerField enumeration omits it). Ship styles that need no texture child (ComposedVolumeStyle, ShadedVolumeStyle) or accept a validator exception for colour-by-density. |
| MP-24 | **Volume children need explicit containerField.** `ImageTexture3D` under `VolumeData` needs `containerField="voxels"` (and `segmentIdentifiers` for SegmentedVolumeData); without it X_ITE files it under `texture` and silently draws nothing useful. A MetadataSet as first child of the Transform needs `containerField="metadata"`, and only one is allowed, so nest source, processing and segments sets inside one wrapper. |
| MP-25 | **(R,S,A) is a mirror image.** Axes x = patient right, y = superior, z = anterior are left-handed. Use x = left (DICOM LPS columns map straight through), y superior, z anterior, and read the in-plane direction from ImageOrientationPatient: this series has rows running toward anterior, so it displays upside down if the header is ignored. |
| MP-26 | **Check orientation on an image, not on one statistic.** A bone-centroid test passed or failed on contrast-filled bowel; an axial slice shows spine, kidneys and table at the low-z side at a glance. Grade the left/right claim L when it rests on the header alone. |
| MP-27 | **HU bands are not segments.** Four ids by threshold inside a flood-fill body mask are cheap and honest if graded S; the FMA term offered for a band can be wrong in a given scan (gas band = bowel gas, not Lung). Keep the real organ link for a labelled dataset (TotalSegmentator, CC BY 4.0). Software GL draws the segmented shader very slowly: do not quote timings. |
| MP-28 | **Never trust an organ-label header for alignment.** The NIH pancreas NIfTI has an arbitrary affine origin. Try all 8 axis flips against the CT and keep the one whose label voxels are most uniform in HU (here only the slice flip: 105 +/- 20 HU, 100 percent soft tissue, next best 41 std). Show every trial in the page; it is the evidence. |
| MP-29 | **A human label separates what density bands cannot.** Every pancreas voxel sat inside the v6 soft-tissue band, so the band view hid the organ. A named annotation (FMA:7198) is a better denotes source than a threshold, but still grade L: annotator and accuracy are not audited. |
| MP-30 | **Reference shipped files across versions, hash-checked.** v7 loads v6's intensity NRRD by relative url and asserts its sha256 against v6's summary at build time and in the page; no copy, no drift. |
