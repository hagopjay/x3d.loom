## Use it on a project

1. Paste [kit/templates/KICKOFF-PRE.md](kit/templates/KICKOFF-PRE.md) and [HANDOFF-POST.md](kit/templates/HANDOFF-POST.md) as the first message, with `LOOM-v1.md` attached.
2. Run the witnesses into a run folder outside the project, then accept and write a receipt:

```bash
kit/loom grammar  PROJECT --evidence RUN/evidence --files 'path/*.x3d'
```
```bash
kit/loom traps    PROJECT --evidence RUN/evidence --files 'path/*.x3d' --host strict
```
```bash
kit/loom command  PROJECT --evidence RUN/evidence --name truth -- python3 -m your.gate args
```
```bash
kit/loom foldback PROJECT --evidence RUN/evidence --patch PROJECT/integration/your.patch \
    --target ~/src/the-real-repo --base 1a2b3c4 --consumer "python3 -m pytest -q tests" \
    --scorer 'tests/**' --scorer 'tests/expected/*.json' --impl 'src/**'
```
`--scorer` declares the oracle closure (scorer code, helpers, expected data, config); its files are hashed at the base. `scorer_unchanged` is true only when that closure is declared and the patch leaves it alone (and, with `--impl`, touches nothing outside the declared implementation). No declaration means `unknown`, which `x3d-static/v3` refuses. When the patch does edit the declared scorer, the base scorer is put back over the patched tree and run again; green only under the patched scorer is a fail.
Globs are Loom's own, the same on every Python: `**/` matches zero or more folders, `*` and `?` stay inside one path segment, and a pattern matches files, not folders (`tests/**` matches every file below `tests/`). The scorer inventory is the whole working tree matched against those globs, so a renamed, added or removed scorer file counts, and a symlinked scorer is recorded with its link text and the hash of what it resolves to: a patch that edits a symlink's target changes the scorer. The base-scorer replay runs in a fresh clone with the base scorer restored file by file; if the restored inventory does not equal the base inventory the record is an `error`, not a pass. Known limit: a scorer that reads files outside its declared globs (an import, a data file) is still yours to declare.
Publication fold-backs are target-bound: the patch is frozen and hashed once, applied to a clean clone of the target at `--base`, and the target's own command runs before and after. A patch that edits the oracle (a test file, or a file the consumer names) is marked `scorer changed`. Without `--target` the patch goes into an empty repository and the record says `target_bound: false`; `x3d-static/v2` and `/v3` refuse that.
```bash
kit/loom play     PROJECT --evidence RUN/evidence --tapes 'tapes/*.tape.json' --levels 'levels/*.x3d' --runner tools/replay.mjs
```
```bash
kit/loom physics  PROJECT --evidence RUN/evidence --runs 'runs/*.physics.json' --hosts chromium,firefox,webkit,node --max-waivers 0 --require-takeover
```
```bash
kit/loom record   PROJECT --evidence RUN/evidence --name eyes --status not_run --reason "why"
```
```bash
kit/loom accept   PROJECT --evidence RUN/evidence --profile kit/profiles/x3d-static-v3.json
```
```bash
kit/loom receipt  PROJECT --evidence RUN/evidence --profile kit/profiles/x3d-static-v3.json --subject "name" --out RUN/receipt.json
```
Use `x3d-static-v3.json` for anything published. `x3d-static.json` (v1) is LEGACY: it accepts hand-declared passes and an empty-repository fold-back, and stays only so old receipts can be re-checked against the profile they named.

Exit codes: 0 passed, 1 contract violation (a stable code is printed), 2 instrument or input error. Set `LOOM_PYFLAGS=-O` to run everything optimised; the gates still hold. Grammar and Meaning use the x3d_mcp fork at `~/Projects/x3d/x3d_mcp`, or `--fork` / `LOOM_FORK` to point elsewhere.

## Publishing (law 16)

`kit/loom sweep . DEST --rules kit/profiles/public-sweep.json` writes a public copy: model and vendor names become neutral labels, costs and Drive ids are withheld, and the copy fails if any forbidden pattern survives (`SWEEP-REPORT.json`). The rules file stays private, since it lists the names it removes.
DEST must be disjoint from the source in both directions (the same folder, a parent of it, or a folder inside it is refused before anything is touched). The copy is staged beside DEST: a clean copy replaces DEST; a copy with residue is left at `DEST.sweep-failed` and DEST is kept as it was.
